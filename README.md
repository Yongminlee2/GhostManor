# 기묘한 유령 저택 (GhostManor)

> 코믹 × 호러 포인트앤클릭 방탈출 모바일 게임 — Flutter, 세로 화면, 챕터 1 완성

얼굴도 모르는 괴짜 삼촌에게 저택을 상속받아 찾아간 날, 현관문이 잠긴다.
저택의 유령들이 "상속 자격 시험"을 시작하는데 — 무섭게 굴려고 애쓰지만 어딘가
허술하고 웃긴 유령들과 함께, 방 여섯 개를 풀어 저택의 비밀에 다가가는 이야기.

## 개발 취지

시중의 모바일 방탈출 게임 다수가 "자물쇠 → 비밀번호 → 다음 자물쇠"의 반복에
머무른다는 문제의식에서 출발했다. 이 프로젝트의 목표는 세 가지다.

1. **기믹 다양성** — 자물쇠 일변도를 벗어난 8종의 상호작용:
   클릭 패턴(횟수·순서), 재료 수집+다단계 조합, 방 사이를 넘나드는 교차 단서,
   상태 변화(조명·야광), 제스처(문지르기·드래그), 사운드 단서(두드려 찾기),
   유령과의 상호작용, 순서 연주(오르간). 폰을 실제로 흔들어야 풀리는 퍼즐도 있다.
2. **어렵지만 공정하게** — 모든 답은 화면 안 관찰만으로 도달 가능해야 한다.
   외부 지식 요구 금지, 픽셀 헌팅 금지(핫스팟 최소 폭을 코드 수준에서 강제),
   음소거 유저를 위한 사운드 단서의 시각(대사) 병행. 막히는 구간은
   3단계 힌트(방향→구체→정답)가 받친다.
3. **분위기의 이중주** — 공간·조명·사운드는 으스스하게, 유령들의 대사와 행동은
   코믹하게. 공포와 유머가 서로를 살리는 톤을 지향했다.

## 게임 구성 (챕터 1)

| # | 방 | 담당 유령 | 핵심 기믹 |
|---|---|---|---|
| 1 | 현관 (튜토리얼) | 집사 유령 고스포 | 탭·조합·문지르기·교차 단서 학습 |
| 2 | 거실 | 겁주기 담당 부우 | 촛대 클릭 패턴, TV 단서, 유령 달래기 |
| 3 | 서재 | 사서 유령 너덜 | 잉크 문지르기, 색 책 순서 입력, 이중 잠금 문 |
| 4 | 주방 | 요리사 유령 국자 | 유령 수프 2단계 조합, 두드려 소리로 찾기 |
| 5 | 지하실 | 겁쟁이 유령 덜덜 | 어둠/야광 상태 전환, 와인통 드래그, 폰 셰이크 |
| 6 | 다락방 (최종) | 고스포 재등장 | 모은 음표 카드 4장으로 오르간 연주 → 반전 엔딩 |

거실의 기름병이 서재의 녹슨 경첩을 열고, 방마다 모은 음표 카드가 다락방의
오르간을 연주한다 — 방들이 아이템으로 이어지는 챕터형 설계가 이 게임의 축이다.

## 기술적 특징

- **선언형 방 정의**: 방 하나 = Dart 파일 하나. 벽면·핫스팟(비율 좌표)·오버레이·
  힌트를 선언형으로 기술하고, 특수 기믹만 그 파일 안의 커스텀 위젯으로 구현.
  방 추가 시 엔진 수정이 필요 없다.
- **단일 상태 리액티브 구조**: 게임의 모든 상태는 `GameState`(플래그 맵+인벤토리)
  하나. UI는 이 객체에만 반응하고, 퍼즐 로직은 위젯 없이 순수 함수로 분리되어
  **헤드리스 테스트가 가능**하다 — 방마다 "정답 시퀀스를 실행하면 클리어된다"를
  자동 테스트로 증명한다.
- **에셋 무의존 동작**: 이미지가 없으면 파일명 라벨 블록, 소리가 없으면 무음으로
  동작한다. 코드와 아트를 완전히 병렬로 제작할 수 있었던 핵심 결정.
- **저장 안정성**: 상태 변화 자동 저장(디바운스) + 백업 슬롯(파손 시 복구) +
  중단 지점 자가 치유(클리어 직후 앱이 죽어도 재개 시 자동 전진).
- **힌트 시스템**: 퍼즐별 3단계 힌트(방향→구체→정답)를 전부 무료 제공 —
  어려운 난이도를 공정하게 받친다.

## 기술 스택

- Flutter 3.44 / Dart 3.12 — 세로 고정, Android(iOS 프로젝트 동시 유지)
- 의존성 3개만: `shared_preferences`(세이브) · `audioplayers`(사운드) ·
  `sensors_plus`(셰이크 감지)
- 상태관리 라이브러리 없음 — `ChangeNotifier` + `AnimatedBuilder`로 충분하게 설계

## 빌드와 실행

이 저장소는 Windows에서 사용자 홈 경로에 비ASCII 문자가 포함된 환경까지
지원하도록 빌드 래퍼를 제공한다. **모든 flutter 명령은 래퍼로 실행한다:**

```bash
.\tool\f.cmd pub get
```

```bash
.\tool\f.cmd test
```

```bash
.\tool\f.cmd build apk --release
```

- 래퍼 없이 직접 실행하면 비ASCII temp 경로 환경에서 `flutter test`가
  0xC0000409로 종료될 수 있다 (래퍼가 `TEMP`/`GRADLE_USER_HOME` 등을 ASCII
  경로로 고정한다 — 경로는 환경에 맞게 `tool/f.cmd`에서 수정).
- gradle 설정 일부(minSdk 줄 등)는 Flutter 도구가 빌드 때마다 관리한다 —
  **커밋된 상태 = 도구 출력**이라 빌드 후에도 트리가 깨끗해야 정상이다.
