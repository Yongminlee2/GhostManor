# 기묘한 유령 저택 (GhostManor) — 설계 문서

- 날짜: 2026-08-12
- 상태: 사용자 승인 대기
- 프로젝트 경로: `C:\workAndroid\GhostManor` (ASCII 경로 강제 — 기존 Flutter 빌드 환경과 동일 체계)

## 1. 개요

세로 화면 포인트앤클릭 방탈출 게임. 코믹+으스스한 유령 저택을 무대로, 자물쇠 일변도가 아닌 다양한 기믹(클릭 패턴·재료 조합·상태 변화·제스처 등)을 어려운 난이도로 제공한다. 일러스트는 Codex로 생성한다.

- 표시 이름(가칭): 기묘한 유령 저택 — 출시 전 최종 확정
- applicationId(가칭): `com.yongmin.ghostmanor` — 첫 Play 업로드 전 최종 확정(업로드 후 변경 불가)
- 타깃: 방탈출·퍼즐 매니아 (어려운 난이도 선호층)

## 3. 게임 디자인

### 3.1 스토리 프레임

얼굴도 모르는 괴짜 삼촌이 남긴 저택을 상속받아 찾아갔더니 현관문이 잠긴다. 저택의 유령들이 "상속 자격 시험"을 시작한다. 유령들은 무섭게 굴려고 애쓰지만 어딘가 허술하고 웃긴다(코믹 담당). 공간·조명·사운드는 으스스함 담당. 최종 방 클리어 시 코믹 반전 엔딩.

### 3.2 방 구성 (6개, 순차 해금)

| # | 방 | 역할 | 배치할 기믹 계열 |
|---|---|---|---|
| 1 | 현관 | 튜토리얼(~15분): 탭·아이템 획득/사용·벽면 전환·조합 학습 | 클릭 패턴(쉬움), 수집+조합(쉬움) |
| 2 | 거실 | 본편 시작 | 클릭 패턴, 상태 변화(조명), 유령 상호작용 |
| 3 | 서재 | 관찰 중심 | 교차 단서, 순서 입력, 문지르기 |
| 4 | 주방 | 조합 중심 | 수집+조합(다단계), 사운드 단서 |
| 5 | 지하실 | 어둠 연출 | 상태 변화(야광), 드래그, 흔들기 |
| 6 | 다락방 | 최종 — 앞 방들의 단서 총집결 | 교차 단서(전 방 회수), 순서 연주, 유령 상호작용 |

- 방마다 벽면(씬) 2~4개, 좌우 화살표로 회전. 서랍·금고 등은 클로즈업 화면으로 확대.
- 각 방의 구체 퍼즐(정답 값·단서 배치)은 구현 단계에서 방 단위로 설계한다. 이 문서는 기믹 계열 배치까지만 확정한다.

### 3.3 기믹 카탈로그 (8종)

1. **클릭 패턴** — 특정 사물을 정해진 횟수·순서로 탭 (예: 초상화 왼쪽 눈만 3번)
2. **수집+조합** — 인벤토리에서 아이템 2개 합성 (양초+성냥→불 켠 초)
3. **교차 단서** — 한 방의 단서를 다른 방에서 사용
4. **상태 변화** — 행동으로 방이 변함 (불 끄면 야광 낙서, 유령에게 물건 주면 가구 이동)
5. **제스처** — 문지르기(먼지 닦기), 드래그(가구 밀기), 흔들기(1곳만)
6. **사운드 단서** — 두드려서 소리 다른 곳 찾기. 음소거 유저용 시각(진동 표현) 병행 필수
7. **유령 상호작용** — 유령이 원하는 걸 주면 길이 열림, 코믹 대사 포인트
8. **순서 연주** — 피아노 건반·종 등을 단서 순서대로 입력

### 3.4 난이도 원칙

- 어렵되 공정하게: 모든 답은 화면 안 관찰로 도달 가능해야 한다. 외부 지식 요구 금지.
- 픽셀 헌팅 금지: 핫스팟 최소 크기 보장(화면 폭의 8% 이상).
- 막힘 방지는 3단계 힌트가 담당(§6). 난이도를 힌트로 보완하는 구조.

## 4. 기술 아키텍처

### 4.1 스택·의존성

패키지 4개 고정: `shared_preferences`(세이브), `audioplayers`(사운드), `google_mobile_ads`(보상형), `sensors_plus`(흔들기). 이외 추가 금지 — 필요가 증명되면 그때 추가.

### 4.2 폴더 구조

```
lib/
  core/
    game_state.dart      # 플래그 Map<String,int> + 인벤토리 — 유일한 게임 상태 (ChangeNotifier)
    save_service.dart    # 상태 변화마다 자동 저장 (JSON → shared_preferences)
    models.dart          # Room / Scene(벽면) / Hotspot / Item
    scene_view.dart      # 벽면 렌더 + 핫스팟 히트테스트 + 상태 오버레이 + 클로즈업
    inventory_bar.dart   # 하단 인벤토리 (아이템 선택·조합 UI)
    hint_service.dart    # 퍼즐별 3단계 힌트 + 광고 게이트
    audio_service.dart   # BGM/효과음
    strings.dart         # 모든 UI·대사 텍스트 상수 (영어판 대비 단일 지점)
  rooms/
    room1_foyer.dart … room6_attic.dart   # 방 하나 = 파일 하나
  main.dart              # 타이틀 / 방 진입 / 설정(음량·진행 리셋)
```

### 4.3 핵심 모델과 방 정의 방식

- `Hotspot` = 이미지 대비 **비율 좌표 사각형** + 표시 조건(플래그 식) + 액션 목록.
- 액션 종류: 플래그 설정/증가, 아이템 지급/소비, 클로즈업 열기, 벽면 전환, 대사 표시, 효과음, 커스텀 위젯 열기.
- 각 방 파일은 `Room` 객체를 선언형으로 리턴. "3번 클릭"·"순서 입력"은 플래그 정수 카운팅으로 표현. 피아노 연주처럼 특수한 기믹만 그 방 파일 안 커스텀 위젯으로 구현(escape hatch).
- 조합 규칙: `(아이템A, 아이템B) → 아이템C` 테이블 하나로 전역 관리.

### 4.4 데이터 흐름

탭 → 핫스팟 히트테스트 → 조건 검사(GameState 플래그) → 액션 실행 → 상태 변경 → notifyListeners → UI 갱신 + 자동 저장.

### 4.5 세이브

- 저장 내용: 전체 플래그 + 인벤토리 + 현재 방/벽면. JSON 한 덩어리.
- 쓰기 성공 후 직전본을 백업 슬롯에 유지 — 로드 실패 시 백업으로 복구.
- 설정에 "진행 초기화" 제공 (allowBackup 복원으로 세이브가 남는 경우의 유저 탈출구 겸용).

### 4.6 해상도 전략

- 씬 일러스트 1024×1536 기준 1장. 핫스팟은 비율 좌표라 기기 화면 크기 무관.
- 상태 변화(불 꺼짐·서랍 열림)는 씬 재생성 대신 **부분 오버레이 이미지**를 겹친다 — Codex 생성량 절감의 핵심.
- 방 진입 시 해당 방 이미지 프리로드.

## 5. 아트 파이프라인 (Codex)

### 5.1 스타일 가이드

모든 생성 프롬프트에 공통 접두어를 붙인다(프로젝트에 `art/style-guide.md`로 저장):
"코믹 호러 카툰 스타일, 두꺼운 외곽선, 보라·남색 어두운 톤에 따뜻한 촛불 오렌지 포인트, 귀엽지만 으스스한 분위기" 계열. 첫 방 생성 시 확정 문구를 굳히고 이후 전 에셋에 동일 적용.

### 5.2 에셋 목록

| 종류 | 수량 | 규격 |
|---|---|---|
| 벽면 씬 | 방 6개 × 2~4장 ≈ 18장 | 1024×1536 |
| 클로즈업 | ~20장 | 1024×1024 |
| 상태 오버레이 | ~15장 | 해당 부위 크기 |
| 아이템 아이콘 | ~30개 | 512×512 투명 배경 |
| 유령 캐릭터 | 3~4종 × 표정 2 | 투명 배경 |
| 타이틀·UI 프레임 | 소량 | — |

### 5.3 생성 절차

방 1개 분량씩 생성 → 게임에 넣어 검증 → 다음 방. 전량 선생성 금지(스타일 어긋남 손실 최소화).

## 6. 힌트·광고

- 퍼즐마다 힌트 3단계: 방향 제시 → 구체 지목 → 정답. 1단계 무료, 2·3단계는 보상형 광고 각 1회.
- 광고 로드 실패(오프라인 포함) 시 재시도 안내, **누적 3회 실패면 무료 지급** — 광고 때문에 유저를 가두지 않는다.
- 배너·전면 광고 없음(v1). 몰입 장르라 역효과.

## 7. 에러 처리

- 세이브: 백업 슬롯 복구(§4.5).
- 광고: 실패 폴백(§6).
- 이미지: 방 진입 시 프리로드(§4.6). 로드 실패 자산은 재시도 후 자리표시 색 블록 + 진행 차단 없음.

## 8. 테스트 전략

- **방별 정답 시퀀스 테스트**: 방마다 정답 액션을 순서대로 실행해 탈출 플래그가 서는지 검증하는 자동 테스트 1개씩. 퍼즐 배선 꼬임(클리어 불가)을 잡는 최소 안전망. 방 수정 시 반드시 함께 갱신.
- 조합 테이블·힌트 게이트·세이브 라운드트립 단위 테스트 소량.
- 출시 전 실기기 1회 완주 (빌드 통과 ≠ 클리어 가능).
- 릴리스 빌드 검증: 에셋은 pubspec 명시 방식만 사용(동적 리소스 참조 금지 — 릴리스 스트리핑 함정 회피).

## 9. 출시 계획

1. Play스토어 내부 테스트 → 프로덕션.
2. 스토어 문구에 광고·결제·무료 언급 금지(기존 원칙). 데이터 보안 신고에는 광고 SDK를 정확히 기재.
3. iOS: 순수 Flutter + 공식 플러그인만 사용하므로 코드 수정 없이 빌드 가능한 상태 유지. Mac 또는 클라우드 빌드(Codemagic 등) + Apple 개발자 계정 준비되면 App Store 진행.
