# 개발일지

핵심 의사결정과 트러블슈팅 기록. 시간순.

## 1. 기획과 설계 (2026-08-12)

**장르 문제의식**: 모바일 방탈출 다수가 자물쇠·비밀번호의 반복. 기믹 8종
(클릭 패턴/조합/교차 단서/상태 변화/제스처/사운드/유령 상호작용/순서 연주)을
방마다 겹치지 않게 배치하는 것을 1순위 목표로 잡았다.

**아키텍처 비교 검토** — 세 가지 안을 저울질했다.

| 안 | 장점 | 기각/채택 이유 |
|---|---|---|
| A. JSON 데이터 주도 엔진 | 방 추가가 데이터 작업 | 기각 — 독특한 기믹마다 엔진 타입을 먼저 만들어야 해서 기믹 다양성이 스키마에 갇힘. 방 6개에 과설계 |
| B. 방 = 순수 코드 | 자유도 최대 | 기각 — 인벤토리·세이브·힌트가 방마다 중복 |
| C. 공통 코어 + 선언형 방 정의 | A의 일관성 + B의 자유도 | **채택** — 방=파일 1개, 특수 기믹만 커스텀 위젯 |

**부수 결정**: 세로 고정(한 손 플레이), 언어중립 퍼즐(그림·숫자·기호만 —
영어판 대비), 힌트 3단계+보상형 광고(장르 표준), 챕터형(방 사이 아이템 연계).

## 2. 코어 엔진 — 테스트 주도 (2026-08-12)

GameState → 아이템/조합 → 세이브(백업 슬롯) → 씬 모델 → SceneView/인벤토리 →
힌트/광고 순으로, 전부 테스트 먼저 작성 후 구현. 이 단계의 교훈들:

- **직렬화 테스트의 함정**: JSON 라운드트립 테스트가 "일시 상태 제외"를
  검증한다고 믿었지만, 일시 상태를 non-null로 만들지 않고 돌려서 회귀를 못 잡는
  가짜 안전망이었다. 검증 대상 속성을 실제로 자극하고 나서 단언하도록 수정.
- **위젯 테스트의 프레임 타이밍**: 새로 마운트된 `Image.asset`의 errorBuilder는
  한 프레임 뒤에 해석된다 — 오버레이 표시 테스트에 `pump()` 한 번이 더 필요했다.
- **테스트 헬퍼 이름 짓기**: 로컬 헬퍼를 `find`로 지었다가 flutter_test의
  전역 `find` 파인더를 가려 위젯 테스트가 통째로 컴파일되지 않았다. `findHotspot`으로 개명.

## 3. 빌드 파이프라인 사건: 광고 SDK × Gradle 9 (2026-08-12)

새 Flutter 템플릿(Gradle 9.1/AGP 9.0.1)에서 `google_mobile_ads`가 빌드 불가 —
SDK 쪽 gradle 스크립트가 Gradle 9와 비호환(업스트림 이슈 확인, 수정 계획 없음 상태).

- 전역 pub 캐시를 패치하는 우회는 기각(재현 불가·다른 프로젝트 오염).
- **저장소 안에서 Gradle 8.14 + AGP 8.12로 고정**해 해결. 도구 체인은 프로젝트가
  소유해야 한다는 원칙.

**후속 사건 — 도구의 되돌림**: Flutter 빌드 도구가 매 빌드 시작마다
`minSdk` 줄과 gradle.properties 플래그를 자기 기준으로 되돌려 쓴다는 것을 발견.
빌드마다 복원하는 프로토콜로 버티다가, 세 번의 빌드로 "되돌린 상태로도 빌드가
항상 성공한다"를 실증한 뒤 **도구 출력을 정본으로 커밋**해 문제를 영구 종결했다.
(effective minSdk는 Flutter 기본값으로, 광고 SDK 요구 23+를 충족함을 빌드
성공으로 검증.) 이후 gradle 빌드 후에도 작업 트리가 깨끗하다.

## 4. 튜토리얼 방과 앱 셸 (2026-08-12)

현관 방으로 전체 파이프라인(선언형 방 + 커스텀 기믹 + 정답 시퀀스 테스트 +
아트 의뢰 문서)을 관철. 셸에서 나온 굵직한 수정:

- **비동기 뒤 setState 가드**: 광고 시청 대기 중 힌트 시트를 닫으면
  dispose 후 setState 크래시 — `context.mounted` 가드.
- **세이브 타이머 수명**: 자동 저장 디바운스 타이머에 해제 수단이 없어
  위젯 teardown에서 pending-timer 실패 — `SaveService.dispose()` 신설로 근본 수정.
- **엔딩 상태의 영속화**: "챕터 완료"를 위젯 필드에 뒀더니 완료 후 이어하기가
  클리어된 방에 갇혔다 — 저장 플래그에서 파생되는 getter로 교체.
- **플래그 네임스페이스**: 방 1이 `got_key` 같은 전역 이름을 쓰고 있었다.
  세이브가 방 사이에 공유되므로 방 2가 같은 이름을 쓰면 저장이 오염된다 —
  세이브가 하나도 없는 시점에 전 플래그를 `foyer_` 접두어로 일괄 개명하고
  네이밍 규칙을 문서화.

## 5. 방 2~6 콘텐츠 (2026-08-12)

방마다 설계표(핫스팟 좌표·플래그·대사·힌트 전문)를 먼저 확정하고 구현.
공용 기믹은 승격(`RubbableScene` — 문지르기 위젯을 코어로 추출, 원샷 가드 추가).
방마다 정답 시퀀스 함수(`solveXxx`)를 공용 라이브러리에 쌓아, 마지막에
**여섯 방을 하나의 상태로 연속 클리어하는 통합 테스트**로 챕터 무결성을 증명했다
(서재 앞 기름병, 다락 앞 카드 4장 보유를 경계에서 단언). 첫 실행에 통과.

세부 교훈:
- 지하실 셰이크는 센서 스트림이 자동 테스트 불가 — 판정을 순수 함수로 분리하고
  10연타 폴백(접근성 겸용)을 테스트 경로로 삼았다. 위젯 테스트는 sensors 채널
  모킹이 필요했다(채널 활성화 실패는 스트림 onError가 아니라 프레임워크 에러로
  보고된다는 것을 소스 추적으로 확인).
- 오르간 연주 완료 후 건반 탭이 배열 범위를 벗어나는 잠재 크래시 —
  완료 후 no-op 가드와 전용 테스트.

## 6. 아트 파이프라인 (2026-08-12)

스타일 가이드(공통 프롬프트 접두어)와 방별 의뢰 문서(파일명·크기·**코드와 동일한
비율 좌표**)를 저장소에 두고, 생성된 이미지를 그대로 `assets/`에 넣으면 코드 수정
없이 반영되는 구조. 방 1~3분 42장을 제작·검수 완료.

- **검수 항목**: 규격/투명 채널, 오버레이 크롭의 좌표 정합(픽셀 단위로 일치),
  퍼즐 정답 그림의 정확성(TV 촛불 2·4번 점화, 색 순서 파→초→빨→노, 시계 3시).
- **캐릭터 스프라이트 교훈**: 유령 오버레이를 "씬에서 잘라내기" 방식으로 의뢰했더니
  배경이 함께 구워져 벽에 겹칠 때 이중으로 보였다. "배경 없이 전신만, 투명 PNG"
  규칙을 가이드에 명문화하고 재제작 — 이후 캐릭터는 전부 깨끗하게 나왔다.
- **아트 정합 조정**: 서재의 색 책이 지정 위치보다 한 선반 위에 그려짐 —
  그림 품질이 좋아 재생성 대신 코드 좌표를 그림에 맞추는 방향으로 조정
  (의뢰 문서에 조정 이력 기록).

## 7. 출시 전 총점검에서 잡은 크리티컬 2건 (2026-08-12)

전 코드 총검토에서, **112개 테스트가 전부 통과함에도** 실기기에서 게임을 막을
결함 2건을 발견했다. 둘 다 테스트가 id로 핫스팟을 직접 호출해 히트테스트
레이어를 우회했기 때문에 보이지 않던 부류다.

1. **핫스팟 가림**: 히트테스트는 뒤에 선언한 핫스팟이 우선하는데, 거실의 큰
   벽난로 rect가 나중에 선언되어 필수 촛대의 유효 탭 영역을 화면 폭의 ~2%로
   줄이고 있었다. 선언 순서 재배열로 수정하고, **모든 방·모든 핫스팟의 중심점이
   자기 자신으로 해상되는지 검사하는 회귀 테스트**를 추가해 이 결함 부류를
   영구히 차단했다(z순서 규칙도 문서화).
2. **클리어 소프트락**: 클리어 다이얼로그의 "다음 방" 버튼에만 전진 로직이 있어,
   시스템 뒤로가기로 다이얼로그를 닫거나 그 순간 앱이 종료되면(자동 저장이 이미
   "표시함" 플래그를 남긴 뒤라) 영구히 갇혔다. 전진을 다이얼로그가 닫힌 뒤로
   옮기고, 재시작 시 좌초된 저장을 감지해 자동 전진하는 자가 치유를 추가.
   좌초 상태를 재현하는 회귀 테스트 포함.

> 교훈: "테스트 전부 통과"와 "실제로 동작"은 다르다. 테스트가 우회하는 레이어가
> 무엇인지 항상 물어야 하고, 그 레이어에도 회귀망을 깔아야 한다.

## 8. 출시 정책: 광고 미탑재 (2026-08-12)

무광고 출시로 방향을 정하고 광고 SDK를 완전히 제거했다(`google_mobile_ads`
의존성, `lib/core/ads.dart`, 매니페스트/Info.plist의 앱 ID 메타데이터 전부
삭제). 힌트 3단계는 전부 무료로 전환 — 광고 로드 실패·재시도 같은 예외
경로가 통째로 사라져 힌트 서비스가 순수 동기 함수가 됐다. 부수 효과로
스토어 데이터 보안 신고에서 광고 SDK 관련 항목을 뺄 수 있게 됐다.

## 9. 챕터 1 하드코어 리마스터 (2026-08-13)

첫 완주 평가가 뼈아팠다: 제작자 기준 10분 클리어, 일직선 퍼즐, 상태 변화
없는 그림, "사진 교체"로 느껴지는 전환. 챕터를 늘려서 해결될 문제가 아니라
판단해 챕터 1을 백지에서 재설계했다.

**정량 기준을 먼저 세우고 테스트로 강제했다.** 방마다 벽면 3개, 상호작용
15~20개, 진입 직후 병렬 스레드 2개 이상(서로 교차 잠금), 정답 시퀀스
15스텝 이상(챕터 합계 134스텝 — 종전의 약 2.5배). 이 기준은 문서가 아니라
`hardcore_metrics_test`가 지킨다 — 어느 방이 퇴행하면 방 이름으로 즉시
드러난다.

**정공법으로 돌아섰다.** 핫스팟 반짝임을 지우고, 유령 대사에서 정답 직결
정보를 전부 걷어냈다(성격·너스레만 남김). 대신 힌트를 시간 잠금(진입 5분
후 1단계, 이후 3분당 1단계)으로 열어 막힌 사람의 최후 수단은 유지했다.
단서는 전부 "답을 아는 방법"일 뿐 게이트가 아니다 — 편지를 안 읽어도
시계가 3시면 서랍은 열린다. 이 원칙도 방마다 부정 테스트로 고정했다.

**"사진 교체" 비판은 오브젝트 레이어로 답했다.** 배경판(오브젝트 제거) +
투명 스프라이트 분리 세트로 와인통이 실제로 밀리고 지구본이 실제로
갈라진다(`SceneObject`, AnimatedPositioned 트윈). 다단계 오브젝트(수프
냄비 5단계, 빙실 해동 3단계)는 상태마다 그림이 바뀐다.

**사운드는 전부 실음원 또는 자체 제작으로.** CC0 팩(Kenney·OpenGameArt)에서
23슬롯을 교체하고, 못 구한 9슬롯(오르간·유령 웃음·노이즈류)은 합성기를
새로 설계했다 — 오르간은 디튠 2랭크+드로바 배음+홀 잔향. BGM은 5분대
호러 앰비언스 루프. 출처는 [CREDITS.md](CREDITS.md).

**아트 63장을 두 배치로 반영했다.** 규격·투명도·단서 내용(시계 시각, 문양
순서, 별자리 모양, 라벨 개수)을 전수 검수하고, 벽면 소품 위치가 코드
좌표와 어긋난 다섯 방을 실측으로 재배선했다. 검수에서 잡은 것들: 정답을
반쯤 유출하는 유색 타일, V자로 나온 W자 별자리, 문지르기 전후가 같은 그림
(먼지 베일을 직접 합성해 해결), 풀프레임 오버레이의 소형 rect 스쿼시 2건.

> 교훈: 아트는 "도착"이 아니라 "정합"이 완료 조건이다. 그림 속 단서가
> 코드의 정답과 다르면 퍼즐은 조용히 죽는다 — 단서 내용 대조를 검수
> 체크리스트의 1순위로 올렸다.

## 10. 챕터 2 「이층의 기억」 (2026-08-13)

리마스터 직후 같은 날 이어서 챕터 2를 완성했다. 목표는 분량 확장이 아니라
**"방탈출을 하며 스토리를 느끼게"** — 첫 완주 평가에서 가장 아팠던 지적을
코어 장치로 답하는 것.

**기억 회상 씬을 코어에 넣었다.** 방마다 핵심 퍼즐을 풀면 세피아 톤 정지
일러스트+자막 2~3줄이 재생된다(`MemoryPlayer` — 탭 전진, 타이머 없음).
삼촌 에드가의 과거가 방마다 한 조각씩 드러나고(가족→자장가→유령과의 첫
만남→병상의 결심→봉인의 밤), 마지막 방에서 다섯 조각이 맞춰진다. 회상은
보상이지 게이트가 아니라는 원칙을 지키되, 회상 그림 속 촛불 개수(1·2·3·4·
꺼진 초)가 최종 제단 퍼즐의 순서 단서를 겸한다 — 서사 장치와 퍼즐 단서를
한 몸으로.

**저택 2층, 방 5개 + 엔딩.** 거울에 유령 물건만 안 비치는 안방, 태엽 기차가
실제로 트랙을 달려 서랍을 밀어 여는 아이 방, 실린더 재생 소리 횟수가
다이얼 코드가 되는 서고, 촛불을 전부 꺼야 깨어나는 봉인의 방. 하드코어
