# 테스트 전략과 현황

## 실행

```bash
.\tool\f.cmd test
```

```bash
.\tool\f.cmd analyze
```

반드시 래퍼(`tool\f.cmd`)로 실행한다 — 비ASCII 사용자 홈 환경에서 temp 경로를
ASCII로 고정해야 flutter_tester가 정상 동작한다(자세한 이유는 HANDOVER.md).

## 현황

- **112개 전부 통과** (2026-08-12 기준), `flutter analyze` 무결점.
- 릴리스 APK 빌드 검증 완료.

## 테스트의 다섯 층

| 층 | 파일 | 검증 대상 |
|---|---|---|
| 엔진 단위 | game_state / items / save_service / models / hint_service | 상태머신, 조합 테이블(순서 무관·실패 시 불변), 세이브 라운드트립·백업 복구·디바운스·dispose, 힌트 광고 게이트(실패 3회 무료·카운터 리셋) |
| 위젯 | scene_view (+각 방의 커스텀 기믹) | 비율 좌표 히트테스트, when 게이트, 오버레이 조건 표시, 에셋 부재 폴백, 인벤토리 선택/조합 UI, 시계·문지르기·셰이크(연타 폴백)·오르간 배선 |
| 방별 정답 시퀀스 | roomN_*_test + solutions.dart | **"이 방은 실제로 클리어 가능하다"의 증명** — 정답 절차를 핫스팟 단위로 실행하며 각 단계를 단언. 부정 테스트(잠금 우회 불가, 틀린 순서 리셋 등) 동반 |
| 챕터 통합 | chapter1_integration_test | 하나의 GameState로 6방 연속 클리어. 방 경계에서 교차 아이템(기름병, 음표 카드 4장) 보유를 단언 — 방 간 배선 파손을 즉시 검출 |
| 히트테스트 해상망 | hotspot_resolution_test | 모든 방·모든 벽면에서 각 활성 핫스팟의 중심점이 자기 자신으로 해상되는지(뒤 선언 우선 규칙 반영). 의도적 가림은 주석 달린 예외 맵으로 관리 |

## 설계 원칙

1. **퍼즐 로직은 헤드리스로** — 판정 함수(`toggleCandle`, `tapBook` 등)는
   GameState만 받는 순수 함수라 위젯 없이 테스트한다. 위젯 테스트는 "제스처 →
   함수 호출" 배선만 검증한다.
2. **정답 시퀀스는 공용 라이브러리로** — `test/solutions.dart`의 `solveXxx`가
   방별 테스트와 통합 테스트에서 재사용된다. 방을 고치면 두 층이 함께 반응한다.
3. **전제 조건은 명시** — 교차 아이템이 필요한 방의 단독 테스트는 setUp에서
   해당 아이템을 지급하고 주석으로 출처(어느 방의 보상인지)를 밝힌다.
   통합 테스트만은 아무것도 지급하지 않는다 — 그게 존재 이유다.
4. **가짜 안전망 금지** — 단언 대상 속성을 실제로 자극한 뒤 단언한다
   (예: 일시 상태 제외 직렬화 테스트는 일시 상태를 non-null로 만들고 돌린다).
5. **테스트가 우회하는 레이어를 인지** — id 기반 핫스팟 호출은 히트테스트를
   우회한다. 그래서 해상망 테스트가 별도로 존재한다. 새 상호작용 레이어를
   추가하면 같은 질문을 던질 것.

## 알려진 자동화 불가 항목 (실기기 검증 필요)

- 지하실 셰이크의 **실제 센서 경로** (가속도 크기 > 12) — 자동화는 10연타
  폴백 경로만 커버. 실기기에서 흔들기 1회 확인 필요.
- 보상형 광고의 실제 표시 흐름 (현재 테스트 유닛 ID).
- 전체적인 체감 — 좌표 정합, 연출 타이밍, 난이도. **챕터 1 실기기 1회 완주가
  최종 수용 기준이다.**
