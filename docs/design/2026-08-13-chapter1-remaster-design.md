# 챕터 1 리마스터 설계 문서

- 날짜: 2026-08-13
- 상태: 확정 (전 항목 결정 완료, 완성 후 일괄 검수 방식)
- 배경: 실기기 전체 플레이 평가 — 제작자 기준 10분 클리어, 일직선 퍼즐,
  과잉 안내, 상태 디테일 부재, 전환 연출이 "사진 교체"로 느껴짐, 사운드 품질 한계.
  결론: 챕터 추가로는 해결 불가, 챕터 1 자체를 하드코어 기준으로 전면 재설계.

## 1. 목표

- 신규 유저 기준 **방당 20~40분, 챕터 전체 2~3시간** 첫 클리어.
- 방마다 힌트 없이 **1~2번은 확실히 막히는** 지점.
- 디자인(그림체·캐릭터·톤)은 현행 유지 — 바꾸는 것은 퍼즐 깊이·디테일·연출·소리.

## 2. 하드코어 정량 규칙 (방마다 강제 — 어기면 미완성)

| 규칙 | 기준 |
|---|---|
| 병렬성 | 방 진입 시 착수 가능한 퍼즐 스레드 ≥ 2, 서로 교차 잠금(A의 보상이 B의 중간에 필요) |
| 추리 거리 | 단서는 원형 그대로 사용 불가 — 최소 1회 변환·해석·조합을 거쳐야 답 (목표 2단계) |
| 상호작용 밀도 | 방당 15~20개 (퍼즐 관여 8~12 + 조사 리액션 5~8, 장식도 탭하면 대사) |
| 상태 디테일 | 진행을 바꾸는 오브젝트는 시각 상태 ≥ 3단계 (예: 냄비 빈→물→재료→완성) |
| 크로스룸 | 방마다 이전 방의 기억/아이템 요소 ≥ 1 |
| 오답 리액션 | 잘못된 시도에 전용 대사·사운드 (전 퍼즐) |
| 정량 하한 | 정답 시퀀스 스텝 수 ≥ 15 (기존 6~10의 약 2배) — 자동 테스트로 단언 |
| 금지 | 픽셀 헌팅(핫스팟 폭 ≥ 0.08 유지), 외부 지식, 무의미 반복 노가다 |

## 3. 안내 정책 (정공법)

- ✨ 글린트(핫스팟 반짝임) **코드 삭제**.
- 유령 대사에서 **정답 직결 정보 전면 제거** — 성격·너스레·분위기·조사 리액션만.
  (미스디렉션은 허용하되 "가짜 단서"는 금지 — 무관한 수다까지만.)
- 힌트 **시간 잠금**: 방 진입 5분 후 1단계 해금, 이후 단계당 3분.
  구현: 방 진입 시각(epoch 초)을 `entered_at_<roomId>` 플래그에 저장,
  힌트 시트가 열릴 때 경과만 계산(타이머 없음 — 테스트 안전).
  잠김 상태 UI: "🔒 4:12 후 열림" 카운트 표시(시트 열 때 계산, 실시간 갱신 불필요).
- 힌트 3단계 구성·무료 정책은 유지 (막힌 사람의 최후 수단).

## 4. 엔진 확장

### 4-1. 오브젝트 레이어 모션 (디졸브 금지 정책)
큰 상태 전환(통 이동, 지구본 갈라짐, 문 개방 등)은 전체 프레임 교체가 아니라
**배경판 + 분리된 오브젝트 스프라이트**로 표현한다.

- `SceneObject` 모델 신설: {스프라이트 이미지(투명 PNG), 상태별 rect(위치·크기),
  현재 상태를 결정하는 상태 함수, 상태 전환 시 positional tween(600ms, easeInOut)}.
- 씬 렌더 순서: 배경판 → SceneObject들 → 파셜 오버레이 → 탭 레이어.
- 와인통: 배경판(통 없음, 쪽문 노출) 위에 통 스프라이트가 왼쪽→오른쪽으로 실제 이동.
- 지구본: 좌반·우반 스프라이트가 각각 바깥으로 벌어짐(2개 오브젝트 동시 트윈).
- 기존 전체 프레임 오버레이(트렁크 등)는 오브젝트 분리로 순차 전환.
- pumpAndSettle 안전: 트윈은 상태 전환 시 1회 실행되는 유한 애니메이션.

### 4-2. 월드 조합 슬롯 패턴
인벤토리 내 조합 대신, **월드 오브젝트에 아이템을 직접 넣는** 것을 표준으로.
(냄비에 재료 하나씩 투입, 보면대에 카드 꽂기 — 기존 `using` 패턴의 표준화라
엔진 신규 코드는 적고, 넣을 때마다 상태 그림이 반드시 바뀐다.)
인벤토리 조합은 "휴대 가능한 소품 2개" 결합(성냥+양초류)에만 남긴다.

### 4-3. 삭제
- 글린트 렌더·타이머 분기 삭제.
- (숨쉬기·리플·벽 슬라이드·클로즈업 줌·아이템 플라이·유령 둥실은 유지 —
  단, 유령 둥실 진폭·주기는 자연스럽게 재튜닝.)

## 5. 아트 파이프라인 v2

- **분리 스프라이트 + 배경판**: 움직일 오브젝트는 "배경에서 오브젝트를 제거한
  배경판" + "오브젝트만 투명 스프라이트" 2장 세트로 의뢰(원본 edit 방식).
- **상태 단계 시리즈**: 다단계 오브젝트(냄비 등)는 단계별 edit 시리즈로 의뢰.
- **벽면 3번째**: 방당 신규 벽면 1장(기존 스타일 유지, 신규 퍼즐 소품 배치).
- 의뢰서는 **일괄 1건**(`art/remaster-assets.md`)으로 조기 작성 — 코드 구현과
  이미지 생성이 병렬로 진행되도록. 도착 전에는 라벨 블록으로 동작.
- 검수는 합성 스크립트 전수검사(기존 절차) + 스프라이트 투명·정렬 확인.

## 6. 사운드 파이프라인 v2 (실음원)

- 소스: **CC0/저작권 무관 무료 소스에서 개발 측이 직접 다운로드** (Kenney.nl
  오디오 팩, OpenGameArt CC0 등 — 로그인 불필요·직다운 가능한 곳만).
- 전 슬롯(폴리·앰비언스·BGM) 실음원으로 교체. 부족한 슬롯만 합성 유지.
- 포맷: wav/ogg → 게임 포맷으로 변환·정규화(볼륨 평준화) 후 파일명 매핑.
- `docs/CREDITS.md`에 파일별 출처·라이선스 기록(CC0라도 기록 — 검증 가능성).
- 최종 품질 판정은 실기기 청취(사용자).

## 7. 방별 재설계

방 6개·유령·스토리 골격 유지. 퍼즐은 방마다 백지에서 §2 규칙으로 재설계하되
기존 기믹 중 반응이 좋은 것(오르간 연주, 셰이크, 문지르기, 두드리기)은
재배치해 살린다. 벽면 2→3개, 클로즈업 약 2배.
**방별 상세 설계표(스레드 구조·핫스팟·상태 단계·대사·힌트 전문)는 구현 계획서가
담는다** — 계획서의 설계표가 구속력 있는 원본이다.

각 방의 재설계 방향 요약:
| 방 | 유지 | 재설계 방향 |
|---|---|---|
| 현관 | 튜토리얼 역할, 시계·문지르기 | 조작 학습은 유지하되 스텝 수 2배·병렬 2스레드 도입(하드코어 맛보기) |
| 거실 | 부우·TV·벽난로 | 촛대 패턴을 다단서 조합형으로, 초상화 시선 코드 등 추리 거리 2단계 퍼즐 추가 |
| 서재 | 너덜·책 순서·문지르기 | 책 순서의 단서를 간접화, 별도 스레드(지도·별자리류) 교차 잠금 |
| 주방 | 국자·수프·두드리기 | 수프를 월드 냄비 슬롯 4단계로, 레시피 단서를 방 안 분산 배치 |
| 지하실 | 덜덜·어둠/야광·셰이크 | 어둠 상태를 퍼즐 전반에 확장(불 켬/끔을 오가며 푸는 구조), 통 이동은 오브젝트 모션 |
| 다락방 | 고스포·오르간·엔딩 | 연주 순서 단서를 다층화(자수+회수 카드+방 기억 조합), 최종 방다운 총합 난이도 |

## 8. 검증 기준

- **정량 자동 테스트**: 방별 solve 스텝 수 ≥ 15 단언, 병렬 스레드 존재 단언
  (진입 직후 서로 다른 스레드의 첫 액션 2개가 모두 실행 가능함을 단언),
  기존 회귀망(히트테스트 해상·통합·시퀀스) 전부 유지.
- **실기기 최종 수용 기준**: 새 세이브로 사용자 플레이 — 첫 클리어가
  "짧다"는 느낌이 아닐 것(목표: 제작 지식 없이 2시간대, 제작자도 1시간+).
- 아트·사운드 포함 완성본 1회 일괄 검수(사용자)로 판정.

## 9. 범위 제외

- 챕터 2 콘텐츠(리마스터 완료·검수 후 별도 설계).
- 스토어 출시 절차(서명 키·아이콘·등록 — 리마스터 검수 통과 후).
- 난이도 선택 모드, 도전과제, 통계 등 부가 시스템.
